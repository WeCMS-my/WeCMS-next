# WeCMS-next 一期范围调整说明

## 1. 调整结论

经重新评估项目交付节奏、当前后端完成情况以及一期可交付目标，WeCMS-next 一期范围正式调整为：

```text
一期目标：基础系统后台 + 前端管理端
```

原计划中准备进入 M2-BE 开发的 CMS 内容管理后端模块，整体移入二期任务，不再纳入一期范围。

---

## 2. 调整前规划

原阶段规划中，M2-BE 初步计划开发 CMS 内容管理后端能力，包括：

* CMS 栏目管理
* CMS 文章管理
* CMS 页面管理
* CMS 标签管理
* CMS 媒体库
* CMS 友情链接
* CMS 内容版本
* CMS 发布日志
* CMS 回收站
* `/api/v1/cms/*` 接口
* `cms_*` 数据表
* CMS 权限码与菜单 seed
* CMS OpenAPI 与质量门禁

该范围功能较完整，但开发体量明显超过一期“基础后台系统”目标。

---

## 3. 调整后规划

调整后，一期不再开发 CMS 模块。

一期只聚焦：

```text
基础系统后端 + 基础系统前端
```

一期保留范围：

* Auth 登录 / 刷新 / 退出 / 当前用户信息
* Users 用户管理
* Roles 角色管理
* Permissions 权限管理
* Menus 菜单管理
* Departments 部门管理
* Posts 岗位管理
* Dicts 字典管理
* Settings 系统设置
* Logs 登录日志 / 审计日志 / 安全事件
* Files 基础文件上传 / 下载 / 预览
* OpenAPI 契约
* Migration / Seed
* Quality Gate
* 前端管理端接入上述系统功能

---

## 4. CMS 模块处理方式

CMS 模块整体移入二期。

二期再单独规划：

```text
Phase 2：CMS Content Management
```

二期 CMS 范围包括但不限于：

* CMS-BE 后端内容管理能力
* CMS-FE 前端内容管理页面
* 栏目 / 文章 / 页面 / 标签
* 媒体库高级能力
* 内容发布
* 内容版本
* 发布日志
* 回收站
* SEO 配置
* CMS OpenAPI
* CMS 权限矩阵
* CMS 菜单 seed
* CMS 质量门禁

一期不创建、不预留、不半实现 CMS 相关接口和表结构。

---

## 5. M2 阶段重新定义

原计划：

```text
M2-BE：CMS 后端
```

现调整为：

```text
M2-FE：基础系统前端管理端
```

M2 的主要目标是把 M1-BE 已验收的系统管理 API 接入前端，形成可操作的后台管理系统。

M2-FE 重点包括：

* 登录页
* Token 存储与自动刷新
* `/auth/me` 会话恢复
* 动态菜单
* 动态路由
* 权限按钮控制
* 用户管理页面
* 角色管理页面
* 权限管理页面
* 菜单管理页面
* 部门管理页面
* 岗位管理页面
* 字典管理页面
* 系统设置页面
* 日志查看页面
* 文件管理页面

---

## 6. M2 不新增 CMS 后端能力

M2 阶段明确禁止新增 CMS 后端能力。

禁止内容：

```text
1. 不新增 /api/v1/cms/* 接口。
2. 不新增 cms_* 数据表。
3. 不新增 CMS 权限码。
4. 不新增 CMS 菜单 seed。
5. 不开发栏目、文章、页面、标签功能。
6. 不开发 CMS 媒体库。
7. 不开发内容发布、版本、回收站。
8. 不开发公开站点渲染。
9. 不引入 CMS 前端页面。
10. 不引入 CMS 相关半成品代码。
```

---

## 7. M2 后端允许范围

M2 阶段后端只允许做前端接入支持性修正。

允许内容：

```text
1. 修复前端接入过程中发现的 API 契约问题。
2. 修复 OpenAPI 与实际接口不一致的问题。
3. 补充前端页面必要的返回字段。
4. 优化 /auth/login、/auth/me 的前端初始化数据。
5. 优化菜单树返回结构以适配前端动态路由。
6. 修复文件上传 / 下载 / 预览在前端接入中发现的问题。
7. 补充缺失的前端接入测试。
8. 维护并保持后端 quality gate 通过。
```

M2 后端支持性修正必须满足：

```text
不扩大一期业务范围；
不引入 CMS；
不破坏 M1-BE 已验收能力；
不降低认证、授权、权限、角色锁定、审计和文件安全规则。
```

---

## 8. 阶段命名调整

调整后的阶段建议如下：

| 阶段               | 名称     | 范围                            |
| ---------------- | ------ | ----------------------------- |
| M0-BE            | 后端基础工程 | 工程结构、认证基础、数据库、OpenAPI 基础      |
| M1-BE            | 系统管理后端 | 用户、角色、权限、菜单、部门、岗位、字典、设置、日志、文件 |
| M2-FE            | 系统管理前端 | 接入 M1-BE，完成基础后台管理端            |
| Phase 2 / CMS-BE | CMS 后端 | 栏目、文章、页面、标签、媒体、发布、版本、回收站      |
| Phase 2 / CMS-FE | CMS 前端 | CMS 管理页面与内容操作后台               |

---

## 9. 调整原因

本次范围调整的主要原因：

1. CMS 模块功能体量较大，不适合与一期基础系统前端并行推进。
2. 当前 M1-BE 已完成系统管理后端能力，最需要的是前端闭环验证。
3. 一期目标应优先交付一个可登录、可授权、可管理的后台基础系统。
4. CMS 涉及内容模型、发布机制、版本记录、媒体关系、SEO 等复杂设计，适合二期单独规划。
5. 将 CMS 后移可以降低一期风险，减少半成品模块进入主线。
6. 前端接入 M1-BE 能更早发现 API 契约、菜单结构、权限模型、文件上传等实际使用问题。

---

## 10. 一期最终目标

调整后，一期最终目标为：

```text
交付一个可用的基础后台管理系统。
```

一期完成后应具备：

* 管理员可以登录后台。
* 登录态可以刷新和恢复。
* 用户可以按权限看到菜单。
* 按钮可以按权限显示或隐藏。
* 用户、角色、权限、菜单、部门、岗位、字典、设置、日志、文件等基础系统能力可以在前端操作。
* 后端 OpenAPI、权限、迁移、seed、质量门禁保持通过。
* 不包含 CMS 功能入口。
* 不调用 `/api/v1/cms/*`。
* 不存在 CMS 半成品代码。

当前一期已完成 M0-BE、M1-BE、M2-FE 基础闭环，后续进入一期后 hardening / 补齐阶段。补齐阶段不重新打开 CMS 一期范围，不引入 AI runtime，不做旧 ThinkPHP runtime compatibility，不复制旧 AdminGate；旧 AdminGate / CSRF 中有价值的职责必须按新架构拆分落地。

---

## 11. 执行要求

从本调整说明生效后，后续开发必须遵守：

```text
1. M2 阶段以 M2-FE 为主。
2. M2 阶段不启动 CMS-BE。
3. M2 后端只允许支持前端接入的小范围修正。
4. CMS 相关需求统一进入二期 Backlog。
5. 任何 CMS 表、接口、权限、菜单、页面都不得进入一期主线。
6. 一期验收以基础系统后台闭环为准。
```

---

## 12. 最终结论

本次范围调整正式确认：

```text
CMS 模块整体移入二期。
一期目标调整为基础系统后台 + 前端管理端。
M2 不新增 CMS 后端能力。
M2 后端只允许做前端接入支持性修正。
```

调整后，下一阶段应进入：

```text
M2-FE：基础系统前端管理端开发
```
